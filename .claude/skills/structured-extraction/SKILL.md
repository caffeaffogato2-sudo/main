# 構造化データ抽出

文書や画像から決められた項目を抜き出し、**毎回同じ形のデータ**として出力するためのスキル。
Anthropic cookbook の「tool use による JSON 抽出」「Vision + tools」「Pydantic 検証」の考え方を、
Claude がそのまま実行できる手順にしたもの。

抽出結果は Excel やノーコードツールにそのまま流し込まれることが多い。
そのため「読みやすい文章」より「形がそろっていて、嘘が混ざっていないこと」が最も重要になる。

## 手順

### 1. 抽出スキーマを決める

スキーマ＝「どの項目を、どの型で出すか」の定義書。先に決めることで、文書ごとに項目名や形式がぶれるのを防ぐ。

- 依頼が下記の定型に当てはまる場合は、そのスキーマを読み込んで使う:

  | 対象 | スキーマファイル |
  |---|---|
  | 議事録・会議メモ | `references/schemas/meeting_minutes.json` |
  | 請求書・見積書・領収書 | `references/schemas/invoice.json` |
  | 名刺・署名欄・連絡先 | `references/schemas/business_card.json` |
  | 仕様書・要求書の要件 | `references/schemas/requirements.json` |

- ユーザーが項目を指定した場合や、定型に当てはまらない場合は、同じ書式（JSON Schema 形式）で新しいスキーマを作る。
  項目が5個を超える、または曖昧な点がある場合は、抽出前にスキーマ（項目名・型・必須かどうか）を短く提示して確認する。
  項目名は英小文字のスネークケース（`due_date`）にすると、後でツールに取り込むときに困らない。
- 作ったスキーマは作業フォルダに `schema.json` として保存する（検証スクリプトで使うため）。

### 2. 抽出する

以下のルールで抜き出す。どれも「後工程で人が気づけない誤り」を防ぐためのもの。

- **書かれていないことは作らない。** 見つからない項目は `null`。推測で埋めると、取り込み後に本物のデータと区別できなくなる。
  推測が役に立つ場面では、値は `null` のまま `_notes` に「〜と推測されるが記載なし」と書く。
- **値の形式をそろえる。**
  - 日付: `YYYY-MM-DD`（和暦・「来週火曜」等は、基準日が文書内で分かる場合のみ変換し、分からなければ原文のまま `_notes` に残す）
  - 金額・数量: 数値型（`1200000`）。カンマ・円記号・「万円」は外す。通貨は別項目にする
  - 電話番号・郵便番号: 文字列（先頭の0が消えないように）
  - 選択肢（`enum`）がある項目: 必ず定義済みの値から選ぶ
- **根拠を残す。** スキーマに `source` 系の項目があれば、原文の該当部分（短い引用やページ番号）を入れる。人が確認するときの手がかりになる。
- **画像の場合**: 読み取れない文字は推測せず `null` とし、`_notes` に「判読不可: 〇〇欄」と書く。手書きや低解像度の部分も同様。
  表は行ごとに配列の要素にし、列見出しをキーにする。
- **複数ファイルの場合**: 1ファイル＝1レコードとし、各レコードに `source_file` を付ける。

### 3. 検証する

出力を JSON ファイルに保存し、付属スクリプトでスキーマどおりか確認する（Python 標準ライブラリのみで動く）。

```bash
python scripts/validate.py --schema schema.json --data output.json
```

- エラーが出たら内容を直して再実行する。ゼロになるまで繰り返す。
- スクリプトを実行できない環境では、必須項目・型・`enum` を目視で確認する。

### 4. 出力する

1. 抽出結果の JSON（ファイル保存＋要点を会話に表示）
2. 依頼が「Excel」「表」「一覧」「CSV」を含む場合は CSV も作る:
   ```bash
   python scripts/validate.py --schema schema.json --data output.json --csv output.csv
   ```
   CSV は Excel で文字化けしないよう BOM 付き UTF-8 で書き出される。明細（オブジェクトの配列）は1行1明細に展開され、
   明細表が2つ以上ある場合（例: 決定事項と宿題）は `output_decisions.csv` のように表ごとに別ファイルになる。
3. 最後に短い報告を付ける:
   - 抽出件数
   - `null` になった項目と理由（記載なし／判読不可）
   - 人の確認が必要な箇所（推測を含む、原文が曖昧 など）

## 出力例

入力（議事録の一部）:
> 11/20 定例。新ダッシュボードは12月リリースで決定。デザイン確定は佐藤さん、11/27まで。

出力:
```json
{
  "meeting_date": "2026-11-20",
  "title": "定例",
  "attendees": [],
  "decisions": [{"content": "新ダッシュボードは12月リリース", "source": "新ダッシュボードは12月リリースで決定"}],
  "action_items": [{"task": "デザイン確定", "owner": "佐藤", "due_date": "2026-11-27", "source": "デザイン確定は佐藤さん、11/27まで"}],
  "_notes": ["年の記載なし。作成日から2026年と判断", "出席者の記載なし"]
}
```
